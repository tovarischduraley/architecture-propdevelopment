# Перечень требований, которым должны соответствовать внешние интеграции

Требования, предъявляемые к внешним интеграциям PropDevelopment в рамках внедрения системы «Умный дом», платёжных шлюзов и партнёров ЖКХ:

- **Шифрование данных при передаче и хранении**  
  + Для всех соединений необходимо использовать TLS версии 1.2 и выше.  
  + Запрещена передача персональных данных (ПДн) по незащищённым каналам связи.  
  + Чувствительные данные (ПДн, биометрические данные, токены) должны храниться исключительно в зашифрованном виде с использованием AES-256.  
  + Резервные копии также должны быть защищены шифрованием.  

- **Применение надёжных протоколов аутентификации и авторизации:**  
  - Для взаимодействия между серверами используется протокол OAuth 2.0.  
  - Для авторизации и проверки прав доступа применяются подписанные JWT токены с ограниченным сроком действия и встроенными механизмами валидации.  
  - При необходимости выполнять авторизацию от имени пользователя (например, в мобильном приложении) применяется OpenID Connect поверх протокола OAuth 2.0.  

- **Сегментация сетевых зон**  
  + Обмен данными с внешними системами должен осуществляться исключительно через выделенную зону безопасности (DMZ или API Gateway).  
  + Внутренние базы данных и сервисы не должны иметь прямой доступ из внешних сетей.  

- **Управление доступом на основе ролей (RBAC)**  
  - Доступ предоставляется только на основании ролей (Role-Based Access Control).  
  - Каждому сервису или пользователю назначаются минимально необходимые права доступа.  

- **Ротация криптографических ключей**  
  - Все ключи шифрования должны обновляться минимум один раз в шесть месяцев.  
  - В случае компрометации — ключи подлежат немедленной замене.  
  - Ключи необходимо хранить в защищённых хранилищах.  

- **Соответствие требованиям действующего законодательства**  
  + Все компоненты интеграции обязаны соответствовать Федеральному закону № 152-ФЗ:  
    - обоснование обработки персональных данных,  
    - применение шифрования,  
    - реализация разграничения доступа,  
    - хранение согласий пользователей.  
  + Биометрические данные (например, изображения лиц и номера автомобилей) обрабатываются исключительно на стороне сертифицированного партнёра. PropDevelopment получает только результат распознавания.  

- **Логирование и аудит**  
  - Все операции с данными и вызовы API должны протоколироваться с указанием времени, источника запроса, действия и результата.  
  - Лог-файлы должны быть доступны для централизованного анализа и аудита (SIEM) и храниться не менее 180 дней.  

- **Интеграция с SIEM-системой**  
  + Все критические события, ошибки и аномалии взаимодействия с внешними системами должны передаваться в SIEM-систему.  
  + Должна быть настроена автоматическая система уведомлений службы информационной безопасности при возникновении инцидентов.  

- **Согласование с ИБ-службой и документация**  
  - Каждая интеграция с внешней системой должна проходить согласование с ИБ-службой PropDevelopment и документально фиксироваться:  
    включать описание API, модель угроз, архитектуру, SLA и ответственных лиц.
